# 7a: CV structure and the immutable original version (ADR-024)

Branch `feat/phase-7a-cv-versions`. Owner decisions for Phase 7 (2026-11-25):
rule-based suggestions now and an LLM later, versions stored as structured
text with a PDF later, and the LLM provider decided later.

## What changed

* `cv.py`:
  * `split_sections()` groups the CV's own lines under recognised headings
    (`SECTION_ALIASES`, plus short all-caps lines as `other`). Bullet markers
    start bullets, and wrapped lines join their bullet. Lines before the first
    heading form a `preamble` section.
  * `create_original()` (idempotent per document; CV documents only),
    `get_version`, `list_versions` and `export_payload`.
* Migration 12 `cv_versions`:
  * one original per document (partial unique index);
  * a CHECK keeps a `tailored` row from existing without parent, target and
    `approved_at`;
  * the trigger `cv_versions_original_is_immutable` aborts any UPDATE of an
    original;
  * cascades on user or document deletion.
* Errors: `CvError` (`invalid_cv`) and `CvVersionNotFoundError`
  (`cv_version_missing`).
* The account export gains `cv_versions`.
* Audit: `cv.original_created` records the document id and section count
  only, never CV text.

## Cost and latency

Splitting is linear in the CV text and runs once per document; later reads
are a single row. No new dependency, no network and no background job.

## Tests

`tests/test_cv.py` (9):

* heading and bullet grouping, with wrapped bullets joined;
* every source word survives the split;
* an unknown all-caps heading becomes `other`;
* an idempotent original;
* the database refuses an UPDATE of the original;
* only a CV can be the source;
* versions are private to their owner;
* versions cascade with the account and appear in the export;
* an empty CV is rejected with a reason.

The export API test expects `cv_versions`.
