# 8d: the email studio screen (ADR-026)

Branch `feat/phase-8d-draft-studio`, stacked on #53 (8c).

## What changed

* `web/app/drafts/page.tsx` and `web/components/draft-studio.tsx`, linked as
  "Drafts" in the header.
* Professors list: the shortlisted professors, each with "Create draft" or
  "Open draft", a status badge (approved or the draft version), and a note
  when no verified email exists. Empty states link to `/matches` (no
  shortlist) and `/cv` (no CV).
* Editor:
  * a plain-text subject and body;
  * Save (a new version), Discard and Regenerate;
  * the recipient, version and attachment line;
  * the §14.2 checks inline: "Must fix" (block, red) and "Suggestion" (warn,
    amber), each with the API's message;
  * the missing-detail flags;
  * evidence, where only http(s) sources become links.
* Approval:
  * "Approve this exact version" sends the shown `version_no`;
  * it is disabled while anything blocks, while changes are unsaved, or while
    no email is verified;
  * an approved draft shows the version and date plus "Withdraw approval";
  * saving after an approval states "Your edit cleared the approval; review
    and approve again."
* `draft_changed` or `draft_lint_blocked` on approval reloads the draft, so the
  current text and the exact lint messages are shown (QA n3 on #53).
* Version history: every kept version, viewable as escaped text.
* Unsaved changes block opening another draft, with a hint. There is no
  polling.
* QA n1 on #53: `drafts.summaries()` no longer reads bodies; with the
  migration-17 triggers, the stored hash plus the version id is enough.
* `web/lib/api.ts` gains the draft types and calls, `web/lib/errors.ts` gains
  the draft codes, and the roadmap marks the draft studio as available.

## Five priorities

* **Latency:**
  * page load is 3 GETs;
  * opening a draft is 1 GET or POST;
  * a save or approval is 1 call that returns the full draft (lint included),
    so nothing reloads.
* **Data structures:** list rows are patched in place from each response, and
  there is no extra fetch.
* **Security:**
  * everything renders as React text; `dangerouslySetInnerHTML` is never used
    (tested with an `<img onerror>` body, and no image element is created);
  * only http(s) evidence becomes a link, with `noopener`;
  * approval is still enforced by the API and the database.
* **UX:**
  * inline checks with exact fixes;
  * an obvious "approval cleared" state;
  * a reload on conflict;
  * version history;
  * empty states;
  * native controls for keyboard use.
* **Cost:** no polling, no LLM.
