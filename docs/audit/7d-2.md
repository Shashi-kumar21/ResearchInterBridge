# 7d-2: the /cv screen, plus QA follow-ups on #47 (ADR-024)

Branch `feat/phase-7d-cv-web`, stacked on #47 (7d-1). The Owner's layout
choice is a separate "CV" page.

## What changed

* `web/app/cv/page.tsx` and `web/components/cv-studio.tsx`, linked as "CV" in
  the header. The screen has four steps:
  1. **Your CV**: uses an uploaded CV document as the immutable original
     ("Use this CV"); with no CV it links to `/documents`.
  2. **Tailor it for**: the shortlisted targets; with an empty shortlist it
     links to `/matches`.
  3. **Suggestions**: one card each, showing the kind, the reason, now versus
     suggested (for reorders), the line or skill concerned and the evidence.
     Buttons: Accept, Reject, Edit (skills and flagged lines only, in the
     student's own words, at most 500 characters), and a one-click Undo once
     decided.
  4. **Before and after**: the line diff, with + and − marks plus
     screen-reader text, the accepted count and the explicit Approve button.
     The approved versions are listed below.
* A decision patches its card in place and re-reads only the preview. There
  is no full reload, and the screen never polls.
* `cv_suggestion_missing` (a pruned run) reloads the latest analysis and says
  why. A 409 shows "accept something first" or "nothing changes".
* `web/lib/api.ts` gains the CV types and calls; `web/lib/errors.ts` gains the
  CV codes; the roadmap marks CV review as available.
* Mobile: the before/after columns stack below 640 px. Keyboard: all controls
  are native buttons, links and form fields.
* QA n1 on #47: `documents.read_document` re-checks the current-policy
  `document_processing` consent, so creating an original or parsing stops
  after a policy change (403 `consent_required`, tested).
* QA n2 on #47: the preview route passes the loaded run into
  `cv_suggestions.preview`, so the run is read once.

## Cost and latency

* Page load: 3 GETs (documents, versions, shortlist).
* Opening a target: one analysis POST plus one preview GET.
* A decision: one PATCH plus one preview GET.
* Approval: one POST.
* No polling, no LLM, no network beyond the API.
