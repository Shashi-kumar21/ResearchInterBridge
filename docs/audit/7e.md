# 7e: optional LLM layer, off by default (ADR-025)

Branch `feat/phase-7e-llm-layer`, stacked on #48 (7d-2). Follows ADR-024:
rules now, the LLM later, and no provider picked yet.

## QA checklist

* **Off by default, zero outbound calls:** the default `llm_provider` is
  `off`, so `rewrite_line` raises `llm_disabled` and no usage row is written.
  `tests/test_llm.py` patches `socket.connect` to fail for every test.
* **Key handling:** read only from `RIB_LLM_API_KEY`; `repr(settings)` and the
  captured logs never contain it (tested).
* **Minimal prompts:** one line plus at most 12 target terms, with email, URL
  and phone redaction (tested).
* **No invention:** `vet_rewrite` rejects new numbers, contact details, empty
  or overlong output. Accepted output carries `ai_generated=True` and is not
  applied without the student's acceptance.
* **Rate limit, caps, timeout:** `LLM_RULE` (30 per hour per account); per-user
  and total 24-hour token caps checked before calling; a timeout maps to
  `llm_unavailable` (all tested).
* **Cache:** keyed per user by sha256 of provider, model, system prompt and
  prompt, for 30 days; identical inputs call the provider once (tested).

## Five priorities (Owner, 2026-11-26)

* **Latency:** a cache hit is one indexed read; calls are bounded by a
  timeout.
* **Data structures:** composite primary key `(user_id, fingerprint)` for the
  cache, and an index on `llm_usage (created_at, user_id)` for the rolling-cap
  sums.
* **Security:**
  * the key is hidden from repr and logs;
  * prompts are redacted;
  * output is vetted;
  * data is per-user and cascade-deleted;
  * the audit holds no text;
  * the layer is off by default.
* **UX:** errors have stable codes and plain messages ("turned off",
  "allowance used up", "did not answer in time"); rule-based suggestions keep
  working.
* **Cost:** off by default, a cache, caps, a rate limit and a small max
  completion size.
