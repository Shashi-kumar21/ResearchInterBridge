# 7b: rule-based, professor-specific CV suggestions (ADR-024)

Branch `feat/phase-7b-cv-suggestions`. Follows the Owner's Phase 7 decisions:
rules now, the LLM later, and no provider picked yet.

## What changed

* `cv_suggestions.analyse()` runs four rules over one CV version against one
  cached target (a faculty member or a program) and stores the result as a run
  with `pending` suggestions:
  1. `reorder_sections`: puts sections that match the target's terms ahead of
     those that don't. The preamble and Education keep their place.
  2. `reorder_bullets`: leads a section with its matching lines (stable
     otherwise).
  3. `surface_skill`: a skill, research keyword or course **from the
     student's confirmed profile** that fully matches a target term but appears
     nowhere in the CV. The reason says to add it only if it is accurate.
  4. `flag_vague`: a matching Experience or Projects line with no number or
     percentage that opens with a duty phrase ("worked on", "helped", ...) or
     is very short. Flagged only; `after == before`, and nothing is written for
     the student.
* Target terms are the faculty member's research interests plus attributed
  paper titles, or the program's research areas plus its name.
* Every suggestion carries evidence: the matched target terms, and for
  `surface_skill` the profile field it came from.
* A run is reused while the CV content hash, the target's `last_checked_at`,
  the profile fields used and `RULES_VERSION` are unchanged.
* Migration 13: `cv_analysis_runs` and `cv_suggestions` (per-user, cascade;
  status `pending|accepted|rejected|edited` for 7c).
* QA nit on #44: headings for certifications, research interests,
  interests/hobbies and references.

## QA checklist

* Only confirmed facts: `surface_skill` reads the student's saved profile only;
  test `test_only_confirmed_profile_items_are_surfaced`.
* No invented text: every `after` line is the student's own CV line or label,
  or a confirmed profile item; test
  `test_no_suggestion_contains_text_the_student_did_not_write`.
* The original stays immutable: analysis writes no `cv_versions` row and the
  version is unchanged (test). Tailored versions still need explicit approval,
  which arrives in 7c (the 7a CHECK constraint refuses an unapproved tailored
  row).
* LLM: there is no LLM code yet. The provider interface and mock arrive in 7e,
  off by default. Analysis makes no outbound call (`socket.connect` is patched
  to fail).
* Cost and latency per analysis: one CV version read, one profile read, one
  target load (the faculty member with papers, or one program), in-memory
  rules over at most a few hundred lines, then one run insert and at most 30
  suggestion inserts. A repeat with unchanged inputs is one indexed lookup
  plus the read. No network, no background job.
* Audit: `cv.analysed` records the target id, the suggestion count and the
  rules version only.
