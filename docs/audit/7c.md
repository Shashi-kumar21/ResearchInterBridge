# 7c: decide on suggestions, approve a tailored CV version, diff (ADR-024)

Branch `feat/phase-7c-cv-approval`, stacked on #45 (7b). Owner choice
(2026-11-25): one suggestion at a time, then a single explicit approval. There
is no "accept all".

## What changed (`cv_suggestions.py`)

* `decide()` sets one suggestion to `accepted`, `rejected`, `edited` or back to
  `pending`.
  * Only `surface_skill` and `flag_vague` can be `edited`, and the edit text is
    the student's own words (whitespace-normalised, at most 500 characters).
  * A reorder can only be accepted or rejected.
  * Nothing is applied when a decision is recorded.
* `preview()` builds the tailored sections from **accepted and edited
  suggestions only**. Pending and rejected ones are never assumed (§3.7). The
  fixed order is: line edits, then bullet reorders (exact index order stored in
  the suggestion), then surfaced skills (appended to Skills, or a new Skills
  section), then the section reorder. Every index therefore still refers to
  the parent version.
* `approve()` is the explicit approval step.
  * It refuses (`cv_nothing_accepted`) when nothing is accepted or edited.
  * It inserts a `tailored` version with parent, target and `approved_at`
    (the 7a CHECK enforces these), and returns the existing version when the
    same content was already approved for that parent and target.
  * The original is never touched.
* `diff()`: a line diff between two versions, with headings, for the
  side-by-side screen in 7d.
* QA n2 on #45: a new run for the same version and target inherits the
  decisions of identical suggestions (same kind, position, before and after)
  and deletes the superseded runs.
* Reorder suggestions now store their exact index `order`, so an accepted
  reorder is applied exactly.
* Audit: `cv.version_approved` records the parent version id, the target and
  the number of applied suggestions. No CV text.

## Cost and latency

Deciding is one row update. Previewing or approving takes a run read, the
parent version and the suggestions, in-memory application, and one insert. No
network, no LLM and no background job.

## Tests

`tests/test_cv_approval.py` (9):

* approval needs an accepted change;
* only accepted and edited changes apply, pending ones are not assumed, and
  the original is unchanged;
* an accepted skill and bullet reorder apply;
* a repeated approval returns the same version;
* decisions are validated, including ownership;
* decisions carry over to a new run and old runs are pruned;
* the diff shows every change;
* the approval audit row has counts only;
* a decision can be undone (back to pending, or rejected) before approval.
